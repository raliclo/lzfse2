lzfse 0.2.0 is the first release published for every platform. Archives are `.tar.zst`, one per platform, each built, stripped and checked by `.github/workflows/release.yml` on a runner of that platform. Verify each with the `.sha256` beside it.

## Downloads

| Archive | Platform | Linkage | Executable (stripped) |
|---|---|---|---|
| `lzfse-0.2.0-linux-x86_64` | Linux x86_64 | glibc; Swift runtime and Foundation linked in | ~58 MB |
| `lzfse-0.2.0-linux-aarch64` | Linux arm64 | glibc; Swift runtime and Foundation linked in | ~57 MB |
| `lzfse-0.2.0-linux-musl-x86_64` | Linux x86_64 | fully static (musl) | ~56 MB |

| `lzfse-0.2.0-macos-x86_64` | macOS Intel | system Swift runtime | ~261 KB |
| `lzfse-0.2.0-macos-arm64` | macOS Apple silicon | system Swift runtime | ~277 KB |

No platform needs Swift installed. The glibc builds need only libc, libm, libstdc++ and libgcc_s, and a glibc at least as new as the build image's (Ubuntu 24.04, glibc 2.39); on an older distribution, or Alpine, use the musl build.

## Install

```sh
zsh install.zsh              # latest release into ~/.local/bin; picks the musl build on a musl system
zsh install.zsh 0.2.0 --musl # Linux: the static musl build explicitly
scoop bucket add raliclo https://github.com/raliclo/lzfse2
scoop install raliclo/lzfse  # Windows x64 and arm64
```

## Checks, per platform

On all eight platforms the build job ran the **stripped** executable from the staged directory and required:

- `lzfse -version` to report exactly what the unstripped build reports: `lzfse 0.2.0 (v0.2.0 / <commit>) <platform>`;
- an `other3` and a `bvx3` encode/decode round trip of a 1.3 MB text file to reproduce the input byte for byte;
- the executable extracted from the packed archive to match the checked one byte for byte.

Linux musl: no program interpreter and no shared library. Linux glibc: no Swift, Foundation, dispatch or ICU library linked dynamically. Windows: run with only the system directories on `PATH`, so every DLL it loads came from the archive. The built-in `lzfse -test` suite was not part of these jobs.

Stripping: Linux `strip --strip-all`, macOS `strip` then an ad-hoc `codesign`, Windows `llvm-strip`. A Windows executable keeps its debug information in a separate `.pdb` that is not shipped, so stripping does not change its size.

## Changes since 0.1.0

0.1.0 was a Windows-only zip in the scoop bucket. The codec is unchanged since then; what is new:

- `lzfse -version` (also `--version`) prints the version, the build id and the platform.
- Releases for Linux (glibc and musl), macOS and Windows, on x86_64 and arm64, built by CI from the tag.
- `install.zsh` installs the right archive for the machine after checking its `.sha256`.
- The scoop manifest now covers Windows arm64 and points at the `.tar.zst` archives.
- `release.zsh` builds, strips, verifies and packs one platform; `publish.zsh --github <X.Y.Z>` tags, waits for CI, verifies every archive from its public URL and rewrites `bucket/lzfse.json`.

## 各平台檢查

八個平台的建置 job 都從暫存目錄執行 **strip 後**的執行檔，並要求：

- `lzfse -version` 的輸出與未 strip 的建置完全相同：`lzfse 0.2.0 (v0.2.0 / <commit>) <平台>`；
- 以 `other3` 與 `bvx3` 各對一個 1.3 MB 文字檔做壓縮／解壓縮往返，結果與輸入逐位元組相同；
- 打包後解開的執行檔與檢查過的那份逐位元組相同。

Linux musl：沒有 program interpreter，也沒有共享函式庫。Linux glibc：沒有動態連結任何 Swift、Foundation、dispatch 或 ICU 函式庫。Windows：以只含系統目錄的 `PATH` 執行，所以它載入的每個 DLL 都來自封存本身。內建的 `lzfse -test` 測試套件不在這些 job 裡。

strip 方式：Linux `strip --strip-all`，macOS `strip` 後重新 ad-hoc `codesign`，Windows `llvm-strip`。Windows 執行檔的除錯資訊放在另外的 `.pdb`（不隨附），所以 strip 不改變它的大小。

## 自 0.1.0 以來的變更

0.1.0 是 scoop bucket 裡只有 Windows 的 zip。codec 自那時起沒有改變；新增的是：

- `lzfse -version`（也接受 `--version`）印出版本、build id 與平台。
- Linux（glibc 與 musl）、macOS、Windows 在 x86_64 與 arm64 上的正式版，由 CI 從 tag 建置。
- `install.zsh` 會依本機選擇正確的封存，驗證 `.sha256` 後安裝。
- scoop manifest 加入 Windows arm64，並改為指向 `.tar.zst` 封存。
- `release.zsh` 建置、strip、驗證並打包單一平台；`publish.zsh --github <X.Y.Z>` 打 tag、等 CI、從公開網址驗證每份封存，再改寫 `bucket/lzfse.json`。
