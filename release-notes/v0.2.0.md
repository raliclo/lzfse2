lzfse 0.2.0. Archives are `.tar.zst`, one per platform, each built, stripped and checked on a runner of that platform by `.github/workflows/release.yml`. Verify with the `.sha256` beside it.

---

**What changed since v0.1.0**

- **The codec is unchanged.** 0.1.0 was a Windows-only zip in the scoop bucket; this release is about how lzfse is built and shipped.
- **Six platforms.** Linux, macOS and Windows, each on x86_64 and arm64. None needs Swift installed: the Linux build is fully static, macOS uses the system's Swift runtime, and the Windows archives carry the Swift runtime DLLs.
- **Linux is musl only.** A glibc build from the Ubuntu 24.04 CI image would need GLIBC_2.38 and a GCC 13 libstdc++, ruling out Ubuntu 22.04, Debian 12 and RHEL 9, so it is not published, as in swift_tar. The static musl build runs on any Linux, Alpine included.
- **`lzfse -version`** (also `--version`) prints the version, the build id and the platform, e.g. `lzfse 0.2.0 (v0.2.0 / <commit>) linux-x86_64-musl`.
- **`install.zsh`** downloads the archive for the machine, checks its `.sha256`, installs it into `~/.local/bin` (or `--prefix`) and checks that the installed copy reports the version asked for.
- **scoop** covers Windows arm64 as well as x64, and points at the `.tar.zst` archives.
- **Released by the maintainer.** CI only builds; `publish.zsh --github` pushes a signed tag, checks every artifact, creates the release with the maintainer's own login, verifies each asset again from its public URL and regenerates `bucket/lzfse.json`.

**v0.1.0 之後的改變**

- **codec 沒有改變。** 0.1.0 是 scoop bucket 裡只有 Windows 的 zip；這一版改變的是 lzfse 的建置與出貨方式。
- **六個平台。** Linux、macOS、Windows，各有 x86_64 與 arm64。都不需要安裝 Swift：Linux 版完全靜態，macOS 使用系統的 Swift runtime，Windows 封存附帶 Swift runtime DLL。
- **Linux 只出 musl 版。** 在 Ubuntu 24.04 的 CI 映像建出的 glibc 版會需要 GLIBC_2.38 與 GCC 13 的 libstdc++，Ubuntu 22.04、Debian 12、RHEL 9 都無法執行，所以與 swift_tar 一樣不發布。靜態的 musl 版在任何 Linux 上都能跑，包括 Alpine。
- **`lzfse -version`**（也接受 `--version`）印出版本、build id 與平台，例如 `lzfse 0.2.0 (v0.2.0 / <commit>) linux-x86_64-musl`。
- **`install.zsh`** 下載符合本機的封存、驗證 `.sha256`、安裝到 `~/.local/bin`（或 `--prefix`），再確認安裝的那份回報的正是指定的版本。
- **scoop** 除了 x64 也支援 Windows arm64，並改為指向 `.tar.zst` 封存。
- **由維護者發布。** CI 只負責建置；`publish.zsh --github` 推送簽章的 tag、檢查每個 artifact、以維護者自己的登入建立 release、再從公開網址驗證每個資產，最後重新產生 `bucket/lzfse.json`。
