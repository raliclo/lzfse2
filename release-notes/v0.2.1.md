lzfse 0.2.1. Archives are `.tar.zst`, one per platform, each built, stripped and checked on a runner of that platform by `.github/workflows/release.yml`, then checked again on a fresh runner with no Swift installed. Verify with the `.sha256` beside it.

---

**What changed since v0.2.0**

- **The codec is unchanged.** `lzfse-cli.swift` has not changed since v0.2.0; this release is about the Windows package and how releases are checked.
- **Windows no longer ships the Swift runtime DLLs.** The Swift runtime is linked into `lzfse.exe` (`-static-stdlib`). The archive carries only the VC++ runtime DLLs it imports (x64: MSVCP140, VCRUNTIME140, VCRUNTIME140_1; arm64: MSVCP140, VCRUNTIME140), so it runs without Swift or the VC++ redistributable installed. A Windows system DLL search finds the bundled copies first.
- **Every archive is checked twice.** `release.zsh` now runs the extracted copy as a user gets it, and a separate CI job unpacks each archive on a runner that never had Swift and checks its `.sha256`, the platform it reports, `lzfse -test` and other3/bvx3 round trips (`verify_archive.zsh`).
- **scoop bucket name.** The bucket is added as `lzfse2`: `scoop bucket add lzfse2 https://github.com/raliclo/lzfse2`, then `scoop install lzfse2/lzfse`.

**v0.2.0 之後的改變**

- **codec 沒有改變。** `lzfse-cli.swift` 自 v0.2.0 以來沒有變動；這一版改變的是 Windows 封存的內容，以及檢查 release 的方式。
- **Windows 不再附 Swift runtime DLL。** Swift runtime 直接連結進 `lzfse.exe`（`-static-stdlib`）。封存只附它匯入的 VC++ runtime DLL（x64：MSVCP140、VCRUNTIME140、VCRUNTIME140_1；arm64：MSVCP140、VCRUNTIME140），所以沒裝 Swift 或 VC++ 可轉散發套件也能執行。Windows 搜尋 DLL 時會先找到附帶的那幾份。
- **每份封存檢查兩次。** `release.zsh` 現在會以使用者拿到的樣子執行解開後的副本；另有一個 CI job 在從沒裝過 Swift 的 runner 上解開每份封存，檢查 `.sha256`、回報的平台、`lzfse -test` 與 other3／bvx3 往返（`verify_archive.zsh`）。
- **scoop bucket 名稱。** bucket 以 `lzfse2` 加入：`scoop bucket add lzfse2 https://github.com/raliclo/lzfse2`，再 `scoop install lzfse2/lzfse`。
